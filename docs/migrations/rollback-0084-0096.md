## Rủi ro khi promote

- `llm_relay_grants`: đã được rebuild từ trước, không có việc gì để promote. Có 0 dòng trên bản sao ngày 2026-11-22.
- `visual_query_patterns`: 0090 tạo bảng rỗng, rồi 0096 rebuild bảng rỗng đó. Không có dòng nào để mất hay trùng. Nếu một ngày nào đó bảng có dữ liệu (không xảy ra trong lần promote này nếu 0090 vẫn rỗng), PK cũ `(workspace_id, topic_tag, shape, example_query)` đã là unique nên PK mới cũng unique với `channel = ''`.


## Cách quay lại

### A. Quay lại code, giữ DB (đường mặc định)

```powershell
cd C:\Users\defu\Documents\videoGenerator-product
powershell -File deploy/product/stop.ps1
git reset --hard <commit trước, promote.ps1 in ra>
npm run build
powershell -File deploy/product/start.ps1
```

- Code product cũ không tham chiếu hai bảng này (đã grep). Hai bảng mới bị bỏ qua.
- Bản product hiện tại có journal dừng ở 0079, DB ở 0086. Migrator của drizzle-orm (`node_modules/drizzle-orm/sqlite-core/dialect.js`, product) chỉ so `created_at` lớn nhất trong bảng ghi với `when` của từng migration trong journal, và không kiểm tra hash. Vì vậy bản này không có migration nào để chạy và khởi động không đổi DB. Đây là đọc mã tĩnh, chưa chạy thử.
- Các migration 0080 đến 0086 chỉ tạo bảng mới, hoặc `ADD COLUMN` với giá trị mặc định (`jobs.input_retry`, `projects.execution_mode`). Không có `DROP`, `RENAME` hay `__new_`. Bản cũ bỏ qua các cột và bảng này.
- Rủi ro chưa đo: bản dev đã ghi dữ liệu vào DB ở 0086 (có thể có trạng thái job hoặc giá trị mà code cũ chưa biết). Không kiểm tra được bằng tĩnh.
- Dữ liệu code mới đã ghi vào `llm_relay_grants` và `visual_query_patterns` sẽ không được code cũ đọc.
- Sau khi khởi động, kiểm tra `.product\api.err.log`. Đây mới là kiểm chứng thật, vì đọc mã tĩnh không thay thế được việc chạy.

### B. Khôi phục backup (khi DB hỏng hoặc bản cũ không mở được)

1. `stop.ps1`.
2. Chọn file `C:\Users\defu\Documents\videoGenerator-backups\app-<thời gian>.db`. `promote.ps1` in đường dẫn này trước khi migrate.
3. Xóa `data\app.db-wal` và `data\app.db-shm`, rồi chép file backup thành `data\app.db`.
4. `git reset --hard <commit trước>`, `npm run build`, `start.ps1`.

Mất: mọi dữ liệu ghi vào DB sau khi promote (job, bài đăng, grant, pattern).
