## What changed in the last window

- **Gate:** SCRIPT_REVIEW auto-passes when off. `outline` parks SCRIPT after the outline and resumes narration on approval. `script` waits after the full script. Draft phase `outline_ready` / `outline_approved` / `done` in `script_drafts.phase` (migration `0104_script_draft_phase.sql`, generated only, not applied to real DBs).
- **Approval path (server):** the outline is approved with `approve_gate` and `gate: "SCRIPT"`. The web panel sends the pipeline approve action for stage `SCRIPT` (`apps/web/src/features/script/ScriptTab.tsx`, `approveOutline`). `orchestrator.approveGate("SCRIPT")` always goes to `approveOutline`, which errors unless SCRIPT is `WAITING_USER` and the draft phase is `outline_ready`. In `script` mode the gate to approve is `SCRIPT_REVIEW`. While the outline waits, the quality repair and the SCRIPT quality hold are skipped (`apps/server/src/registry/tools/pipelineActions.ts`, `outlineWaiting`).
- **MCP:** checked by reading. `approve_gate` is a server registry tool (`apps/server/src/registry/tools/pipelineActions.ts`, `approveGateArgs` uses `gate: PipelineStageSchema`, which includes SCRIPT, and is `.strict()`). `apps/mcp/src/tools.ts` line 56 refuses direct HTTP gate approval for MCP callers and points them to the registry tool. `apps/mcp/src/apiClient.ts` (line 413) sends registry calls to `/api/registry/invoke`, so MCP callers can reach `approve_gate` through the registry. Whether the registry path has any further restriction for MCP callers was not read. `apps/server/src/supervision/leases.ts` line 16 defines `project()` as a project-scoped lease on the `projectId` argument; line 29 lists `approve_gate: project()`. No node-routing rule was found in that file (`node_id` at line 174 is job handling). Not run.
- **Channel default:** `scriptOutlineApproval` is in `ProfileDefaultBriefSchema` and `ProfileDefaultBriefInputSchema` (`packages/shared/src/schemas/profile.ts`). It is **API only**: there is no UI on the profile page. The project form reads it as the initial value (`CreateProjectDialog.tsx` line 159). A strip bug in the output schema was found by reading and fixed.
- **Web (D2):** outline approval panel with the button "Duyệt dàn ý" in the script tab (shown also when `script` is null). The server rejects hook switches and rescore writes while the outline is pending (`scriptService.ts` ~51, ~107, ~730). By reading, the hook-switch and rescore buttons are disabled while the outline is pending (`apps/web/src/features/script/ScriptDraftPanel.tsx` lines 135 and 218). Not run in a browser. The setting is on the project create and edit forms with these option labels: "Tắt: chạy tự động, không chờ duyệt", "Duyệt dàn ý trước khi viết (không duyệt kịch bản sau)", "Duyệt kịch bản sau khi viết". **Not** on `BriefFields` (`BriefSettings` does not carry the field, so it was reverted).
- **Placement:** in `CreateProjectDialog.tsx` the `settings.scriptOutlineApproval` line (257) is inside `if (customize)`, next to `autoRender`. When customize is off, no value is sent and the server default applies. The channel default then applies through the server seed; see "Checked by reading (item 4, channel default)" below.

Deviations: `evidence` is `push_in` (spec: zoom or highlight, graphic call-out); `reveal` is `punch_in` with no hard-cut or no-dissolve control; `payoff` is `pull_out` with no hold; `reflection` is `pull_out` with no dissolve and no longer shots; `transition` is `null`, which keeps the cycle (spec: per preset); `tension` does not shorten shots towards the end of the beat. The frequency cap is `capSec` inside `applyBeatMotion`; by reading, `capSec` is `strongMoveEverySec(preset)`, i.e. `FREQUENCY` in `packages/shared/src/motion/plan.ts` (calm 20, energetic 8, news 10, story 15). The cap is checked only for beat-derived punch_ins (`tooClose` in `packages/shared/src/motion/beatMotion.ts` lines 24–55), while `lastPunchAt` is updated by every final punch_in. So a cycle-derived punch_in can land within `capSec` of a beat punch_in. This limit is not fixed; not run.
